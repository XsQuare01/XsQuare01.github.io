## Global Constraints

- 소스/원문 보존: 노션 "Dynamic programming 2/3"의 줄기(마지막 곱 결정 → 부분 구간 독립성 → 점화식 → 구간 길이순 채우기 → $M[1,n]$)를 지킨다. 확장분(정리·증명 조판, $O(n^3)$ 정정, 괄호화 복원 분리)은 "더 나가면" 등에서 원문 밖임을 명시. 권한 순서: AGENTS > 정본(`docs/writing-rules.md` 6단계) > 이 계획.
- 표기 규약: $M_i$ 는 $d_{i-1}\times d_i$, 사슬 $d_0\dots d_n$. 점화식 $M[i,j]=\min_{i\le k<j}(M[i,k]+M[k+1,j]+d_{i-1}d_k d_j)$, 기저 $M[i,i]=0$.
- 검증 예시: $(3\times2)(2\times4)(4\times2)$ = $d=[3,2,4,2]$ → 두 괄호화 $48$ vs $28$, 정답 $28$.
- 문장: 초안 후 `docs/writing-rules.md` '바른 문장 쓰기'로 훑는다(문두 접속어 최소화 최우선). 코드는 C++ 의사코드.
- 커밋: **Co-Authored-By 트레일러 넣지 않음**. 콘텐츠 편집 중 `.astro` 캐시 삭제 금지.

2. **callout `이 포스트에서 다루는 내용`**(`<div class="callout">`+`<div class="callout-title">`, dp-2와 동일 구조) 불릿 4개:

   - 짧은 구간부터 채우는 2차원 표
   - (더 나가면) 어떤 괄호 순서인지 복원, 복잡도
3. **`## 곱셈 순서가 비용을 바꾼다`** — 행렬 $(p\times q)$ 와 $(q\times r)$ 을 곱하면 결과는 $p\times r$ 이고 스칼라 곱셈은 $p\cdot q\cdot r$ 번. 결합법칙으로 결과는 순서와 무관하지만 비용은 다르다. 예시 $(3\times2)(2\times4)(4\times2)$:
   - `((3×2)(2×4))(4×2)`: $3\cdot2\cdot4 + 3\cdot4\cdot2 = 24+24 = 48$
   - `(3×2)((2×4)(4×2))`: $2\cdot4\cdot2 + 3\cdot2\cdot2 = 16+12 = 28$
   - 이미지: `![두 괄호화의 곱셈 횟수: 왼쪽 48번, 오른쪽 28번.](/images/dp-3/cost-compare.svg)`
4. **`## 마지막 곱셈을 어디서 하는가`** — $M_i\times\cdots\times M_j$ 의 최소 비용을 $M[i,j]$ 로 정의. 최상위 괄호 = 사슬을 둘로 가르는 **마지막 곱** 하나. 그 분할점을 $k$($i\le k<j$)라 하면 왼쪽 $M_i\cdots M_k$, 오른쪽 $M_{k+1}\cdots M_j$. **부분 구간 독립성**: 바깥 행렬이 무엇이든 $M[i,k]$·$M[k+1,j]$ 값은 변하지 않는다. 마지막 곱의 비용은 $(d_{i-1}\times d_k)(d_k\times d_j)$ = $d_{i-1}d_k d_j$. 어느 $k$ 가 최선인지 모르니 전부 시도:
   $$M[i,j] = \min_{i \le k < j}\big(M[i,k] + M[k+1,j] + d_{i-1}\,d_k\,d_j\big)$$
   기저 `<div class="callout callout-key">`: $M[i,i]=0$ (행렬 하나는 곱이 필요 없다).
   - **정리 + 증명**(`<div class="thm">`/`<div class="thm-head">정리 1<span class="en">...</span></div>` 와 `<div class="proof">`+`<span class="proof-lead">증명.</span>`+`<span class="qed">∎</span>`, dp-2와 동일 구조): 최적 부분구조 — $M[i,j]$ 의 최적 괄호화에서 마지막 분할점을 $k^\*$ 라 하면 왼쪽/오른쪽 부분도 각자 최적이어야 한다(아니면 그 부분만 더 싼 괄호화로 바꿔 전체 비용을 줄일 수 있어 최적 가정에 모순). 따라서 $M[i,j]$ 는 모든 $k$ 후보의 최솟값과 같다(상계·하계 양방향).
   - 이미지: `![구간 [i,j]를 k에서 자르면 왼쪽 M[i,k], 오른쪽 M[k+1,j], 합치는 비용 d_{i-1}·d_k·d_j. 모든 k 중 최소가 답이다.](/images/dp-3/split.svg)`
5. **`## 작은 구간부터 채우기`** — $M[i,j]$ 는 자기보다 **짧은** 구간 $M[i,k]$, $M[k+1,j]$ 만 참조한다. 그러니 구간 길이 1(기저)부터 시작해 길이를 늘려 가며 채우면 참조가 항상 준비돼 있다. 2차원 표에서 대각선을 따라 채우는 그림. 코드(아래 그대로):
   ```cpp
   // d[0..n]: Mᵢ 는 d[i-1] x d[i] 행렬.  M₁ x … x Mₙ 의 최소 곱셈 횟수.
   int matrixChain(const vector<int>& d, int n) {
       vector<vector<int>> m(n + 1, vector<int>(n + 1, 0));  // m[i][i]=0: 한 행렬은 곱 불필요
       for (int len = 2; len <= n; len++)              // 구간 길이 2..n
           for (int i = 1; i + len - 1 <= n; i++) {    // 구간 [i, j]
               int j = i + len - 1;
               m[i][j] = INT_MAX;
               for (int k = i; k < j; k++)             // 마지막 곱을 (i..k)(k+1..j)로
                   m[i][j] = min(m[i][j], m[i][k] + m[k+1][j] + d[i-1]*d[k]*d[j]);
           }
       return m[1][n];
   }
   ```
   $d=[3,2,4,2]$ 채움: 길이 2 — $M[1,2]=3\cdot2\cdot4=24$, $M[2,3]=2\cdot4\cdot2=16$. 길이 3 — $M[1,3]=\min(M[1,1]+M[2,3]+3\cdot2\cdot2,\; M[1,2]+M[3,3]+3\cdot4\cdot2)=\min(0+16+12,\;24+0+24)=\min(28,48)=28$. 정답 $M[1,3]=28$.
   - 이미지: `![삼각 표를 대각선(구간 길이) 순으로 채운다. d=[3,2,4,2]에서 M[1,2]=24, M[2,3]=16, M[1,3]=28.](/images/dp-3/table-fill.svg)`
6. **`## 비용 따지기`** — 채울 칸(구간 $[i,j]$, $i\le j$)은 $O(n^2)$ 개, 칸마다 $k$ 후보가 최대 $n$ 개라 $O(n)$. 전체 **$O(n^3)$ 시간, $O(n^2)$ 공간**. (노션이 적은 "$O(n^2)$"는 부분문제 *개수*이지 전체 시간이 아니라는 점을 한 문장으로 짚기.)
7. **`## 더 나가면`**(원문 밖) — 지금 코드는 최소 *비용*만 준다. 어떤 괄호 순서였는지 알려면 칸마다 최선의 분할점 $k$ 를 함께 저장해 거꾸로 되짚으면 된다. 그 복원은 **추가 설명 페이지에서 따로** 다룰 예정이라고 예고(하드 링크 걸지 않음).
8. **`## 마치며`** — dp-1(주어진 점화식을 계산) → dp-2(원소를 포함/제외하는 결정으로 점화식 유도) → dp-3(구간을 어디서 자르는 결정으로 확장)로 아크 정리. 마지막 줄 `[동적 계획법 ② →](/blog/dp-2)` 역링크(dp-2가 dp-1로 링크한 것과 대칭).
