## 1. 원문 확인

### 원천

Notion 「Approximate string matching」 (`전공 과목 페이지 › 알고리즘 수업 정리 › Approximate string matching`, https://app.notion.com/p/392cb27e493080d88ae3e1e863861328). 노션 최종 수정 2026-07-27, 조회 2026-08-26.

### 원문의 핵심 줄기

1. 근사 문자열 매칭은 주어진 문자열과 비슷한 문자열을 찾는 문제다. 검색엔진의 유사어 추천, 유전자 비교, 과제 유사도 검증이 응용으로 적혀 있다.
2. 그러면 '비슷하다'를 어떻게 정의하는가 — 거리 함수 세 가지가 이어진다.
   - **Hamming distance**: 같은 자리끼리 비교하므로 change만 판단한다. 네트워크로 끊어 보내다 글자가 변경될 때 오염 정도를 잴 수 있다.
   - **edit distance**: change에 insert, delete까지 판단한다. 다만 `abc/def`와 `def/abc`처럼 copy·move는 못 잡는다.
   - **weighted edit distance**: 연산마다 가중치를 다르게 둔다. 자판에서 `a`–`s`는 가깝고 `a`–`p`는 멀다. 오타는 잡지만 move는 여전히 못 잡는다.
3. edit distance의 정의: 한 문자열을 다른 문자열로 바꾸는 편집 연산의 최소 수. insert, delete, change만 허용한다.
4. 부분 문제 `D(i, j)`는 `S1[1..i]`와 `S2[1..j]`의 편집 거리다. 답은 `D(n, m)`이고, 이를 구하려면 모든 `i, j`에 대해 계산하므로 값이 `NM`개다.
5. 점화식: `D(i, j)`는 `D(i-1, j-1)`과 `S1[i]`–`S2[j]`의 관계 `t(i, j)`로 분리되고, 단독 insert는 `D(i, j-1)`에, 단독 delete는 `D(i-1, j)`에 각각 비용 1이 붙는다. 네 경우 중 가장 좋은 값을 고른다.
6. 재귀로 풀면 갈래가 셋이라 오래 걸리지만 실제 계산할 값은 `NM`개뿐이라 재사용이 많다. 그래서 DP다.
7. tabular computation: 0번째 글자들의 줄은 `0, 1, …, N`(또는 `M`)이다. 0개의 글자와 비교하기 때문이다. 위·왼쪽·왼쪽위 대각선을 보고 채운다. `v`와 `wr`를 비교하면 두 가지 경우가 가능하다. 각 값은 3번씩 재사용된다. 시간은 `O(NM)`이고 "이보다 빠른 방법은 없다"(증명은 참고자료로), 특수한 경우에는 더 빠른 알고리즘이 있다.
8. traceback: 거슬러 올라가며 무슨 연산이었는지 찾는 것. 답이 여러 개 나올 수 있어 결과가 '영역'으로 나온다.

### 원문 예시

- `ababc`와 `abbc`: Hamming 거리 3, edit distance 1(insert/delete a).
- `abcabcd`와 `abcdabc`: `D(2, 4)`는 `ab`와 `abcd`의 거리, `D(5, 1)`은 `abcab`와 `a`의 거리라는 설명. 두 문자열의 편집 거리 값 자체는 원문에 없다.
- `v`와 `wr`: (1) `v`→`w` change 후 `r` insert, (2) `w` insert 후 `v`→`r` change.
- 원문 이미지 두 장(격자 그림, 점화식 수식)은 S3 서명 URL이라 저장소로 옮기지 않고 SVG로 새로 그린다.

### 원문이 남긴 요청 (그대로 인용)

- `(내가 설명해도 무슨 말인지 모르겠으니 나중에 상세히 설명 부탁)` — `D(i, j)`가 `D(i-1, j-1)`과 `t(i, j)`로 분리된다는 서술 뒤.
- `(내가 말했지만 순환참조같으므로, 조금 풀어서 설명해줘)` — 정답이 insert/delete/match/change 네 연산자로 이루어진 1차원 배열이라는 서술 뒤.
- `증명이 있는데…. (참고 자료로 넣어주라)` — `O(NM)`보다 빠른 방법이 없다는 서술 뒤.
- `(이 내용이 무슨 말인지 구체적으로 포스팅에 설명해줘)` — traceback 결과가 '영역'으로 나온다는 서술 뒤.

네 요청을 닫는 것이 이번 두 편의 존재 이유다. 요청 1·2는 본편의 점화식·연산 열 절, 요청 3은 본편의 비용 절, 요청 4는 추가 설명 편이 받는다.

### 원문의 오류·부정확 (정정 대상)

1. **Hamming distance 예시.** 원문은 `ababc`(길이 5)와 `abbc`(길이 4)의 Hamming 거리를 3이라 했다. Hamming distance는 길이가 같은 두 문자열에만 정의된다. 원문의 관찰(자리끼리 맞춰 보면 세 자리가 어긋난다)은 살리고, "길이가 다르면 정의되지 않는다 → 억지로 자리를 맞추면 삭제 한 번이 뒤를 전부 밀어 어긋남이 3으로 부풀어 보인다"로 바꿔 쓴다. 이 밀림이 곧 insert/delete를 들여야 하는 이유이므로, 정정이 도입의 동력이 된다. Hamming의 제자리 예시는 길이가 같은 쌍으로 따로 든다.
2. **"`O(NM)`보다 빠른 방법은 없다".** 무조건적 하한은 알려져 있지 않다. 알려진 것은 SETH 가정 아래의 조건부 하한이다(Backurs–Indyk 2015: 어떤 `ε>0`에 대해 `O(n^(2-ε))` 알고리즘이 있으면 SETH가 깨진다). 반대로 유한 알파벳에서는 Masek–Paterson(1980)이 로그 인자만큼 빠르고, 편집 거리가 `d` 이하라고 알려진 경우 Ukkonen(1985)의 `O(nd)`가 있다. 원문이 "특수한 경우에는 더 빠른 알고리즘이 존재한다"고 적은 것의 실체가 이들이다. 원문의 주장을 부정하지 않고 **조건을 붙여** 정확히 만든다.
3. **"각각의 값들은 3번씩 재사용된다".** 표 내부 칸에서만 참이다. 마지막 행·열의 칸은 2번, `D(n, m)`은 0번 쓰인다. 본문에서 내부 칸이라는 조건을 밝힌다.
4. **"재귀적으로 풀기에는 3배씩 증가하므로".** 갈래가 셋이라 호출 수가 깊이에 대해 지수적으로 늘어난다는 뜻으로 정확히 쓴다. 규모는 `3^(n+m)`이다.
5. **원문 예시의 값 보강.** `abcabcd`와 `abcdabc`의 편집 거리는 2이고 `D(2,4)=2`, `D(5,1)=4`다(3절). 원문이 값을 적지 않았으므로 계산해 채운다.
6. **값의 개수.** 원문은 계산할 값이 `NM`개라고 적었다. 0행·0열을 포함하면 칸은 `(n+1)(m+1)`개이므로 본문은 후자로 적는다.

## 2. 글 설계

### 2.1 두 편으로 나누는 근거

본편이 닫아야 하는 원문 요청은 셋(점화식의 의미, 순환처럼 보이는 서술, 하한)이고 이것만으로 이미 한 편 분량이다. 네 번째 요청인 '영역'은 최적 정렬이 여럿이라는 사실, 되짚기 규칙, 최적 경로들이 이루는 부분 DAG, 경로 개수 세기까지 딸려 오므로 본편에 넣으면 흐름이 무너진다. `dp-2` + `dp-2-traceback`, `dp-3` + `dp-3-traceback`, `maximum-subarray` + `maximum-subarray-why-extend`가 같은 형태다. 본편은 값을 구하는 데까지, 추가 설명은 구성을 복원하는 데까지 맡는다.

DP 시리즈 번호(④)는 붙이지 않는다. 문자열 쪽 주제를 이후에 이어 갈 여지를 남기고, `maximum-subarray`처럼 링크로만 연결한다.

### 2.3 본편 절 구성

1. **비슷하다를 재려면** — 응용 셋(유사어 추천, 유전자 비교, 과제 유사도)에서 공통으로 필요한 것이 거리 함수라는 점. 정의가 없으면 알고리즘이 시작되지 않는다.
2. **자리끼리 맞추기 — Hamming distance** — 같은 길이 전제, change만 잼. 네트워크 오염 판정이 제자리인 이유(자리가 밀리지 않는 상황). `ababc`/`abbc`를 억지로 맞추면 3으로 부푸는 관찰과 정정. 도판 `align-shift.svg`.
3. **밀림을 허용하기 — edit distance와 가중치판** — insert·delete를 들이면 `ababc`/`abbc`가 1. 가중치판은 자판 거리로. 셋 다 move·copy는 못 잡는다는 원문의 한계를 절 끝에 둔다.
4. **부분 문제** — `D(i, j)`의 정의, 접두사라는 말, `D(2,4)`·`D(5,1)`, 값이 `NM`개. 도판 `subproblem.svg`.
5. **마지막 칸에서 무슨 일이 있었나 (점화식)** — 원문 요청 1을 받는 절. 정렬(alignment)의 마지막 열이 match/change/insert/delete 중 하나라는 경우 분석 → `정리 1` + `증명`(마지막 열을 떼면 남는 것이 더 작은 같은 문제라는 최적 부분 구조). `S1[i]`와 `S2[j]`가 같은지 몰라도 되는 이유를 `t(i,j)`로 흡수. 도판 `recurrence.svg`.
6. **답이 연산의 열이라는 관점** — 원문 요청 2를 받는 절. "정답은 네 연산자의 1차원 배열"이 순환처럼 보이는 이유(정의에 자기 자신이 들어온 것처럼 읽힘)를 짚고, 참조가 언제나 짧은 쪽으로만 일어나므로 순환이 아니라는 것을 보인다. 격자 위의 단조 경로와 연산 열의 대응.
7. **표 채우기** — 0행·0열, 세 이웃, `v`/`wr`의 두 경로(원문), `abcabcd`/`abcdabc` 완성 표와 답 2. 도판 `table.svg`.
8. **비용** — `O(NM)`, 내부 칸이 3번 쓰인다는 조건부 서술, 재귀가 `3^(n+m)`인 것과의 대비. 이어서 하한: 무조건 불가가 아니라 SETH 가정 아래 강한 준이차 시간 불가(Backurs–Indyk), 유한 알파벳에서 로그 인자만큼 빠른 방법(Masek–Paterson), 거리가 작을 때의 `O(nd)`(Ukkonen). 참고 문헌.
9. **코드** — C++ 의사코드. 표 전체를 쓰는 판과 두 행만 굴리는 `O(min(N,M))` 공간 판.
10. **핵심 정리** callout → **더 나가면**(추가 설명 링크) → **마치며**.

### 2.4 추가 설명 절 구성

1. **값과 연산은 다르다** — 표는 최솟값만 담는다. `dp-2-traceback`과 같은 출발점이지만, 여기서는 답이 여럿이라는 점이 본질이다.
2. **거꾸로 읽는 규칙** — 칸마다 "어느 이웃에서 왔는가"를 되묻는다. 대각·위·왼쪽 중 등호가 성립하는 것을 고른다. 도판 `traceback-path.svg`.
3. **동점이면 갈래가 갈린다** — `abcab`/`abcba`에서 `D(5,5)=2`에 이르는 최적 정렬이 셋. 셋을 실제로 나열한다. 도판 `alignments.svg`.
4. **그래서 영역이다** — 원문 요청 4를 받는 절. 최적 경로 전체를 모으면 표 위의 부분 DAG가 되고, 그 경로들이 지나는 칸의 합집합이 '영역'이다. `abcab`/`abcba`의 영역은 공통 접두사 `abc`를 따라간 대각선 뒤로 벌어지는 마름모다. 영역이 좁으면 답이 사실상 하나, 넓으면 정렬이 여럿이라는 해석. 도판 `region.svg`.
5. **경로가 몇 개인지 세기** — 표를 한 번 더 채워 최적 경로 수를 세는 DP(`C(i,j)`의 점화식). `abcab`/`abcba`는 3, 원문 예시 `abcabcd`/`abcdabc`는 1이라는 대비.
6. **어느 정렬을 고를 것인가** — 알고리즘이 정하지 않는다. 유전자 정렬은 gap을 뭉치는 쪽, 오타 교정은 다른 쪽을 고르는 식으로 응용이 정한다는 마무리.
7. **핵심 정리** callout → 본편으로 돌아가는 링크.

### 2.5 용어와 기호 도입 순서

- `S1`, `S2`와 길이 `n`, `m`: 본편 부분 문제 절 첫 문단. 원문 표기를 그대로 쓴다.
- 접두사: 같은 절에서 `S1[1..i]`를 부르는 말로 도입.
- `D(i, j)`: 같은 절. 대문자 `D`는 원문 표기.
- `t(i, j)`: 점화식 절. 원문 표기를 살리되 "같으면 0, 다르면 1"임을 명시.
- 정렬(alignment): 점화식 절에서 "두 문자열의 글자를 위아래로 짝지어 놓은 것"으로 도입. 추가 설명 편이 이 말에 의존한다.
- 격자·경로: 연산 열 절. 표의 칸을 격자점으로, 연산 열을 단조 경로로 부른다.
- `N`, `M` 대 `n`, `m`: 복잡도 표기에서는 원문처럼 `O(NM)`을 쓰고 첨자에는 소문자를 쓴다. 같은 값을 가리킨다는 점을 비용 절에서 한 번 밝힌다.

## 3. 계산 예시 (검증용 원자료)

모든 값은 단위 비용(insert=delete=change=1) DP를 코드로 돌려 확인했다.

### `ababc` / `abbc`

- 자리끼리 맞춘 어긋남: 세 자리(3·4번째가 다르고 5번째는 상대가 없음). Hamming distance로는 정의되지 않는다.
- edit distance: **1**. `ababc`의 세 번째 글자 `a`를 delete.

### `v` / `wr` (원문 예시)

| | – | w | r |
|---|---|---|---|
| **–** | 0 | 1 | 2 |
| **v** | 1 | 1 | 2 |

- 편집 거리 **2**, 최적 정렬 **2개**.
  1. `insert w` → `change v→r`
  2. `change v→w` → `insert r`
- 원문이 든 두 경우와 일치한다.

### `abcabcd` / `abcdabc` (원문 예시)

```
      -  a  b  c  d  a  b  c
   -  0  1  2  3  4  5  6  7
   a  1  0  1  2  3  4  5  6
   b  2  1  0  1  2  3  4  5
   c  3  2  1  0  1  2  3  4
   a  4  3  2  1  1  1  2  3
   b  5  4  3  2  2  2  1  2
   c  6  5  4  3  3  3  2  1
   d  7  6  5  4  3  4  3  2
```

- 편집 거리 **2**. `D(2,4)=2`, `D(5,1)=4`(원문이 지목한 두 칸).
- 최적 정렬은 **1개**: `abc` 뒤에 `d`를 insert하고 마지막 `d`를 delete.
- 최적 경로가 유일하므로 이 예시로는 '영역'을 보일 수 없다. 본편 표 도판에만 쓴다.

### `abcab` / `abcba` (추가 설명 편 예시, 확장)

```
      -  a  b  c  b  a
   -  0  1  2  3  4  5
   a  1  0  1  2  3  4
   b  2  1  0  1  2  3
   c  3  2  1  0  1  2
   a  4  3  2  1  1  1
   b  5  4  3  2  1  2
```

- 편집 거리 **2**, 최적 정렬 **3개**.
  1. `a·b·c` match → `S1[4] a→b` change → `S1[5] b→a` change
  2. `a·b·c` match → `b` insert → `S1[4] a` match → `S1[5] b` delete
  3. `a·b·c` match → `S1[4] a` delete → `S1[5] b` match → `a` insert
- 최적 경로가 지나는 칸(영역): `(0,0), (1,1), (2,2), (3,3), (3,4), (4,3), (4,4), (4,5), (5,4), (5,5)`. 공통 접두사를 따르는 대각선 뒤로 `(3,3)`에서 벌어져 `(5,5)`에서 모이는 마름모다.
- 최적 경로 개수 DP로도 3이 나온다.

## 5. 참고 문헌 (본편 비용 절)

- R. A. Wagner, M. J. Fischer, "The String-to-String Correction Problem", *JACM* 21(1), 1974 — 표를 채우는 `O(NM)` 알고리즘의 표준 출처.
- W. J. Masek, M. S. Paterson, "A faster algorithm computing string edit distances", *JCSS* 20(1), 1980 — 유한 알파벳에서 로그 인자만큼 빠른 방법.
- E. Ukkonen, "Algorithms for approximate string matching", *Information and Control* 64, 1985 — 편집 거리가 `d` 이하일 때 `O(nd)`. 노션 페이지 제목과 같은 제목의 논문이다.
- A. Backurs, P. Indyk, "Edit Distance Cannot Be Computed in Strongly Subquadratic Time (unless SETH is false)", *STOC* 2015, arXiv:1412.0348 — 조건부 하한. 원문이 "증명이 있는데"라고 적은 것에 대응하는 결과.

링크는 arXiv 항목에만 걸고 나머지는 서지 정보로만 적는다. 오프라인이라 DOI 링크의 동작을 확인할 수 없다.

## 7. 남은 불확실성 (리뷰 판정 대상)

- Masek–Paterson의 시간은 문헌에서 `O(n²/log n)`으로도 `O(n²/log² n)`으로도 인용된다. 본문에서는 "유한 알파벳에서 로그 인자만큼 빠르다" 수준으로 쓰고 정확한 지수는 논문 인용에 맡긴다.
- 본편의 연산 열 절이 점화식 절과 겹칠 위험이 있다. 겹치면 앞 절의 마지막 소절로 접는다. 판단은 초고를 쓴 뒤 리뷰에서 한다.
- 가중치판을 얼마나 다룰지. 원문 분량이 짧으므로 한 소절로 두고, 삼각 부등식이 깨지는 가중치 같은 이야기는 넣지 않는다.
- 브라우저 렌더 확인은 불가하다. 도판은 값과 팔레트만 검사한다.
