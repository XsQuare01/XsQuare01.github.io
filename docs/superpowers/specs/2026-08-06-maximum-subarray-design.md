## 1. 원문 확인

### 원천

Notion 「Maximum Subarray」 (`알고리즘 수업 정리 › Maximum Subarray`, https://app.notion.com/p/38dcb27e493080dd8d42d7adf6e26a62). 2026-08-06 조회.

### 원문의 핵심 줄기

1. 문제: 연속된 부분배열 중 합이 최대인 것을 찾아라. 전부 양수면 전체 배열이 답이고, 음수가 섞이면 어려워진다.
2. `O(N^3)`: 모든 부분배열을 나열하고 각각 합을 계산한다.
3. `O(N^2)`: 누적합(prefix sum)을 미리 만들어 두면 구간합이 뺄셈 한 번이다.
4. `O(N)` Idea 1: 각 자리에서 끝나는 최선의 합 하나만 들고 간다. 빈 배열 허용 여부에 따라 갱신식이 갈린다.
5. `O(N)` Idea 2: 각 자리에 대해 "포함하는 최선"과 "포함하지 않는 최선" 두 값을 계산한다.
6. `O(N)` Idea 3: 누적합과 지금까지의 최소 누적합을 계산해 그 차의 최댓값을 답으로 삼는다.

### 원문 예시

배열 `[3, -5, 2, 4, -2, 3, -6, 8]`. 원문에 전체 합 `3-5+2+4-2+3-6+8 = 7`이 적혀 있고, 부분배열 `2~4`(0-indexed)의 합을 `arr[4] - arr[1]`로 구하는 예가 있다.

### 원문이 남긴 물음표 (그대로 인용)

- Idea 1의 "k 배열의 시작점을 이동하면 반드시 k와 같거나 작은 값이 나온다" 옆에 `(이 부분에 대한 추가 설명이 있어야 이해하기 쉬워보임)`.
- Idea 3 마지막 줄에 `(사실 이게 답이 되는지는 모르겠다)`.

두 물음표를 닫는 것이 추가 설명 편의 존재 이유다.

### 원문의 오류 (정정 대상)

원문은 연속 부분배열의 개수를 `N(N-1)/2`로 적었다. 원문 자신의 두 논증을 그대로 따라가면 결과는 `N(N+1)/2`다.

- 논증 1: 시작 인덱스 0에서 N개, 1에서 N-1개, …, N-1에서 1개 → `N + (N-1) + … + 1 = N(N+1)/2`.
- 논증 2: 경계 두 곳을 고른다면 고를 수 있는 경계는 원소 사이·양끝을 합쳐 N+1개이므로 `C(N+1, 2) = N(N+1)/2`.

원문의 논증 구조(두 가지 셈법)는 보존하고 결과 수식만 바로잡는다. 원문 보존 규칙에 저촉되지 않는 사실 정정으로 분류한다. `nC2`라는 표기도 "N개에서 2개"가 아니라 "N+1개의 경계에서 2개"임을 밝혀 고친다.

## 2. 글 설계

### 2.1 두 편으로 나누는 근거

정본 가이드 「본편과 후속 글의 경계」 기준으로 판단한다.

- 본편의 중심 주장: **"자리마다 최선 하나만 들고 가면 한 번의 훑기로 끝난다."** 문제 정의, 세 가지 복잡도, 카데인 갱신식, 빈 배열 허용 여부는 이 주장에 필수라 모두 본편에 둔다.
- 추가 설명으로 분리하는 것: 갱신식이 왜 옳은지의 논증과 누적합 관점(Idea 3). 둘은 "카데인을 어떻게 쓰는가"가 아니라 "왜 그것으로 충분한가"라는 **독립된 질문**을 갖고, 그 글만 읽어도 완결된다. 길이가 아니라 질문의 독립성이 분리 기준이다.
- 추가 설명을 한 편으로 묶는 이유: 두 논증이 같은 결론(`k_j = P_j - min_{i<j} P_i`)으로 수렴한다. 따로 두면 결론이 어느 쪽에도 온전히 담기지 않는다.

시리즈 번호는 붙이지 않는다. 원문이 Dynamic Programming 챕터가 아니라 「알고리즘 수업 정리」 바로 아래에 있고, 글의 축이 DP 계보가 아니라 `O(N^3) → O(N^2) → O(N)` 개선 서사이기 때문이다. 대신 본편에서 dp-2와의 사고 연결을 한 문단으로 명시하고 `/blog/dp-2`로 링크한다.

### 2.3 본편 절 구성

각 절의 역할을 정의/예시/논증/해석으로 표시한다.

1. **도입 blockquote** — 해석. 전부 양수면 전체가 답이고, 음수가 섞이는 순간 어려워진다.
2. **목차 callout** — 구조.
3. **문제** (정의 + 예시) — 연속 부분배열, 합. 예시 배열과 전체 합 7, 정답 9. 도판 ①.
4. **모두 세어 보기 — `O(N^3)`** (논증) — 개수 `N(N+1)/2`를 두 셈법으로, 합 계산 `O(N)`을 곱해 `O(N^3)`.
5. **누적합으로 `O(N^2)`** (정의 + 예시) — `P[i]` 정의, 구간합 뺄셈, `arr[4]-arr[1]=4` 검산. 도판 ②.
6. **자리마다 최선 하나 — `O(N)`** (정의 + 논증 + 예시) — 빈 배열 허용을 먼저 못박고 `k_{i+1} = max(k_i + x, 0)`, 8칸 훑기 표, C++ 의사코드. 도판 ③.
7. **빈 배열을 허용하지 않으면** (정의 + 반례) — `k_{i+1} = max(k_i + x, x)`, `[-3,-1,-2]`로 답이 0과 −1로 갈림.
8. **포함하는가, 포함하지 않는가** (해석) — Idea 2가 `k_i` + 전역 최댓값과 같음. dp-2 연결 문단은 여기에 둔다.
9. **더 나가면** (예고) — 갱신식의 정당성과 누적합 관점을 추가 설명으로 링크.
10. **핵심 정리 callout**, **마치며**.

### 2.4 추가 설명 절 구성

1. **도입 blockquote** — 본편이 넘긴 두 질문.
2. **왜 이어 붙이면 되는가** (논증) — `i+1`에서 끝나고 `x`를 포함하는 부분배열 ↔ `i`에서 끝나는 부분배열(빈 것 포함)의 1:1 대응. 합은 정확히 `s + x`, `s ≤ k_i`는 `k_i`의 정의. 도판 ④.
3. **누적합으로 다시 보기** (논증) — 모든 부분배열 합이 `P_j − P_i` (i ≤ j) 꼴이고 `i = j`가 빈 배열에 대응 → 답 `= max_j (P_j − min_{i≤j} P_i)`. 빈 배열을 허용하지 않으면 `i < j`로 좁힌다. 도판 ⑤.
4. **두 아이디어는 같다** (논증 + 예시) — `k_j = P_j − min_{i<j} P_i`를 귀납으로. 예시에서 두 수열이 `3,0,2,6,4,7,1,9`로 일치.
5. **훑기 세 번은 한 번으로** (해석) — 원문의 "3번 탐색"을 단일 루프로.
6. **핵심 정리 callout**, 본편으로 돌아가는 링크.

### 2.5 용어와 기호 도입 순서

- 본편 3절: `a_1 … a_N`, 부분배열 `a_i..a_j`, "연속".
- 본편 5절: 누적합 `P`. 0-indexed 배열과 `P[-1]` 대신 `P` 앞에 0을 두는 관례를 명시한다(인덱스 기준 혼동 방지).
- 본편 6절: `k_i` = "i에서 끝나는 부분배열 중 최대 합(빈 배열 허용)".
- 추가 설명은 본편 기호를 그대로 쓰고 재정의하지 않는다. 첫 절에서 세 기호를 한 줄로 되짚는다.

## 3. 계산 예시 (검증용 원자료)

배열 `a = [3, -5, 2, 4, -2, 3, -6, 8]`, `N = 8`. 인덱스는 본문에서 1-based(`a_1 … a_8`), 누적합은 `P_0 = 0`부터.

- 전체 합: `3-5+2+4-2+3-6+8 = 7`.
- 누적합 `P_0..P_8`: `0, 3, -2, 0, 4, 2, 5, -1, 7`.
- 카데인(빈 배열 허용) `k_1..k_8`: `3, 0, 2, 6, 4, 7, 1, 9`.
- 각 j에 대한 `min_{i<j} P_i`: `0, 0, -2, -2, -2, -2, -2, -2`.
- `P_j − min_{i<j} P_i`: `3, -2, 2, 6, 4, 7, 1, 9`. `k_j`와 다른 자리는 j=2뿐이고, 그 자리에서 `k_2 = max(-2, 0) = 0`이다. 즉 빈 배열을 허용하는 정의에서는 `k_j = max(0, P_j − min_{i<j} P_i)`이고, `min`에 `P_j` 자신을 포함시켜 `min_{i≤j}`로 두면 정확히 일치한다. **추가 설명 4절의 등식은 `min_{i≤j}` 형태로 쓴다.**
- 정답: `9`, 구간은 `a_3..a_8`(0-indexed `2..7`) = `2+4-2+3-6+8 = 9`.
- 부분배열 개수: `8·9/2 = 36`.
- 원문 검산: 0-indexed 누적합 `arr = [3,-2,0,4,2,5,-1,7]`, 부분배열 `2..4` 합 `= 2+4-2 = 4 = arr[4] - arr[1] = 2 - (-2)`.
- 반례 `[-3,-1,-2]`: 빈 배열 허용 시 답 0, 비허용 시 답 −1(`a_2` 하나).

### 비허용 정의로 같은 배열을 돌린 값

`k'_1 = 3`, 이후 `k'_j = max(k'_{j-1} + a_j, a_j)`: `3, -2, 2, 6, 4, 7, 1, 9`. 최댓값 9로 허용 정의와 같다(답이 양수라 갈리지 않는다). 이 사실을 본편 7절에서 명시해 "정의가 항상 답을 바꾸지는 않는다"를 분명히 한다.

## 5. 기술 검증 준비

- **증명 모듈**: 두 명제를 증명한다. (a) `i+1`에서 끝나고 `a_{i+1}`을 포함하는 부분배열의 최대 합 `= k_i + a_{i+1}` — 대응 관계와 `k_i`의 정의만 쓴다. (b) `max_j (P_j − min_{i≤j} P_i)`가 답 — 부분배열과 인덱스 쌍 `(i, j)`의 대응만 쓴다. (c) 두 수열의 일치는 j에 대한 귀납. 생략 단계 없음.
- **코드 모듈**: C++ 의사코드 2개(허용 / 비허용). 컴파일 검증은 하지 않는다(저장소 관례). 본문 설명·경계 조건·복잡도가 코드와 일치하는지 대조는 §3의 값 표로 한다.
- **계산 예시 모듈**: §3에 입력·중간값·결과를 전부 기록했다. 인덱스 기준(본문 1-based, 누적합 `P_0` 시작, 원문 검산만 0-based)을 명시한다.
- **복잡도 모듈**: 입력 크기 N, 계산 모델은 단위 비용 RAM. `O(N^3)`은 부분배열 수 `Θ(N^2)` × 합 계산 `O(N)`, `O(N^2)`는 부분배열 수 × `O(1)` 뺄셈, `O(N)`은 단일 루프 × `O(1)` 갱신. 모두 최악 기준. 공간은 누적합 `O(N)`, 카데인 `O(1)`.
- **SVG 모듈**: 다섯 장의 라벨·색 의미를 본문과 대조하고 경로·구조 검사 결과를 리뷰 인계에 넣는다.
- **빌드**: `npm run build` 통과 확인.
- **결정적 검사**: `python .claude/review_post.py <파일>` — 문장 내부 줄표(—) 임계치에 걸리지 않게 초안 단계부터 "즉/곧/마침표"로 쓴다.

## 6. 남은 불확실성 (리뷰 판정 대상)

- 원문의 `N(N-1)/2` 정정이 「원문 보존」 범위를 벗어나지 않는지. 논증 구조는 보존하고 결과 수식만 고치므로 사실 정정으로 본다.
- Idea 3의 정당성 증명을 추가하는 것이 원문 의도("모르겠다"고 남긴 상태)를 바꾸는지. 원문이 열어 둔 질문에 답하는 것이므로 의도 위반이 아니라고 본다.
- 추가 설명 4절의 등식이 `min_{i≤j}`여야 한다는 §3의 판단.
