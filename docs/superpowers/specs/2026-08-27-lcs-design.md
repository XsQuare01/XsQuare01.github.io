## 1. 원문 확인

### 원천

Notion 「Longest Common subsequence (LCS)」 (`전공 과목 페이지 › 알고리즘 수업 정리 › Longest Common subsequence (LCS)`, https://app.notion.com/p/395cb27e49308010b3b7e0747c8c6e18). 노션 최종 수정 2026-07-12, 조회 2026-08-27.

**이 페이지에는 서로 독립적인 주제가 셋 있다.** ① LCS ② Sequence Alignment(점수 행렬을 입력으로 받아 정렬 점수를 최대화하는 문제) ③ 최대 공백 정사각형(흑백 이미지에서 검은 점을 포함하지 않는 가장 큰 정사각형). ②와 ③은 LCS와 예시도 논증도 공유하지 않는다. 이번 스펙은 **①만** 다루고 ②③은 각각 별도 편으로 남긴다(사용자 결정, 2026-08-27).

### 원문의 핵심 줄기 (① LCS 범위)

1. LCS는 두 수열의 최장 공통 부분수열을 구하는 문제이고 edit distance와 유사하다. 두 DNA 서열이 얼마나 닮았는지 재는 데 쓴다(23자 `ACCGGTCGACGTAAGCCGGCCAA`와 37자 `TTTCCCACTCGTGTCGACGTGTAAGCCTTAAGGCCAA` 예시).
2. 부분수열은 주어진 서열에서 일부 문자를 삭제한 뒤 남은 문자를 순서대로 이어 만든 서열이다. `ACCGGT`에서 `ACGT`·`CCGG`·`AT`은 부분수열이고, 순서대로 이어지지 않은 `GCT`·`CA`는 아니다.
3. sub-string과 sub-sequence의 차이는 '떨어질 수 있는가'다. 부분수열은 떨어져 있어도 되고 부분문자열은 연속이어야 한다.
4. 공통 부분수열은 두 수열 각각의 부분수열이 되는 수열이고, 그중 가장 긴 것이 최장 공통 부분수열이다.
5. 방법 1(가장 간단한 방법): `X`의 모든 부분수열이 `Y`의 부분수열인지 조사한다. 길이가 `n`이면 부분수열이 `2^n`개이므로 그에 가까운 시간이 든다.
6. 방법 2(DP): `X_i = {x_1, …, x_i}`, `Y_j`, LCS를 `Z = {z_1, …, z_k}`로 두고 마지막 글자로 경우를 나눈다.
   - `x_n = y_m`이고 `z_k = x_n = y_m`이면 이 둘은 LCS에 반드시 포함되고, `Z_{k-1}`은 `X_{n-1}`과 `Y_{m-1}`의 LCS다.
   - `x_n ≠ y_m`이고 `z_k ≠ x_n`이면 `x_n`은 포함되지 않고, `Z_{k-1}`은 `X_{n-1}`과 `Y_m`의 LCS다.
   - `x_n ≠ y_m`이고 `z_k ≠ y_m`이면 `Z_{k-1}`은 `X_n`과 `Y_{m-1}`의 LCS다.
   - `x_n ≠ y_m`이므로 둘 다 LCS에 들어가는 경우는 없다.
   점화식: `i = 0` 또는 `j = 0`이면 `LCS(i, j) = 0`; `x_i = y_j`면 `LCS(i-1, j-1) + 1`; `x_i ≠ y_j`면 `max(LCS(i-1, j), LCS(i, j-1))`.
7. "Edit distance에서 change만 제거한, insert/delete만 남긴 경우와 유사하다. 다만 edit distance는 operation의 개수를 세지만 LCS는 반대로 (전체 − operation 개수)를 센다."
8. 방법 3(Longest path): `writers`와 `vintner`의 LCS는 `iter`이고 눈으로 확인할 수 있다. 경로 그림에서 대각선은 가로와 세로가 같은 글자일 때 생기며, 답은 대각선을 지나친 횟수다. "왼쪽 표에서의 최단 거리는 다르게 말하면 오른쪽 표에서의 최장 거리다(이동이 오른쪽/아래로 제한되어 있는 경우만)."

### 원문 예시

- `ACCGGT`의 부분수열 `ACGT`·`CCGG`·`AT`, 부분수열이 아닌 `GCT`·`CA`.
- DNA 두 서열(23자, 37자). 원문은 값을 적지 않았다.
- `writers` / `vintner` → LCS `iter`.
- 원문 이미지 세 장(경로 그림, 정렬 예시, 점수 행렬) 중 LCS 범위에 드는 것은 경로 그림 하나다. S3 서명 URL이라 저장소로 옮기지 않고 SVG로 새로 그린다.

### 원문이 근거 없이 남긴 주장 (이번 글이 닫는다)

1. **"왼쪽 표의 최단 거리가 오른쪽 표의 최장 거리다."** 한 줄로만 적혀 있고 왜 그런지가 없다. 정확한 형태는 격자 항등식이다. `(0,0)`에서 `(n,m)`까지 오른쪽·아래·대각선으로만 가는 경로가 대각선을 `d`개 쓰면 오른쪽 걸음이 `m-d`개, 아래 걸음이 `n-d`개이므로 대각선 아닌 걸음의 수는 `n + m - 2d`다. 곧 비용 최소화와 대각선 최대화가 같은 문제다.
2. **"LCS는 (전체 − operation 개수)를 센다."** 관계만 흘려 두었다. 등식으로 만들면 삽입·삭제만 허용한 편집 거리가 `n + m - 2|LCS|`다.
3. **"두 글자가 같으면 LCS에 반드시 포함된다."** 원문은 `z_k = x_n = y_m`이라는 조건을 달아 조건부 서술로 만들었고, 그래서 "반드시 포함된다"의 증명 의무가 닫히지 않았다. 교환 논증으로 닫는다. 어떤 최적 짝짓기에서 `x_n`이 짝지어졌다면 그것이 `X` 쪽의 마지막 짝이고, `y_m`이 짝지어졌다면 그것이 `Y` 쪽의 마지막 짝이므로, 둘이 모두 짝지어졌다면 마지막 짝이 `(x_n, y_m)`이어야 한다.
4. **"둘 다 LCS에 들어가는 경우는 없다."** 참이며 위 3의 관찰에서 곧바로 나온다. `x_n ≠ y_m`이면 마지막 짝이 `(x_n, y_m)`일 수 없으므로 둘 중 적어도 하나는 짝지어지지 않는다. 원문은 결론만 적었고 이유가 없다.

### 원문의 오류·부정확 (정정 대상)

1. **`X_i`를 '부분 수열'이라 부른 것.** `X_i = {x_1, …, x_i}`는 접두사다. 부분수열은 이 글의 주인공이라 두 말이 섞이면 정의가 무너진다. 접두사로 부른다.
2. **`LCS(m, n)`.** `X`의 길이를 `n`, `Y`의 길이를 `m`으로 두었으므로 구할 값은 `LCS(n, m)`이다. 인덱스가 뒤바뀌었다.
3. **`x_1 ≠ y_j`.** `x_i ≠ y_j`의 오타다.
4. **부분수열의 개수 `2^n`.** 인덱스 부분집합의 수는 `2^n`이 맞지만 서로 다른 *문자열*의 수는 중복 때문에 더 적다. `ACCGGT`는 `2^6 = 64`가 아니라 36개다. 완전탐색 비용의 근거는 부분집합의 수이므로 원문의 논증은 그대로 두고 조건만 붙인다.

## 2. 글 설계

### 2.1 단독 1편으로 내는 근거

되짚기와 '영역'은 [편집 거리 추가 설명](/blog/edit-distance-traceback)이 이미 다뤘다. LCS의 답 복원은 같은 기계이므로 다시 쓰면 중복이다. 링크로 넘기고, 이 글은 LCS 자체와 두 관계(바꾸기 제거, 최단↔최장)에 지면을 쓴다. 어려운 곁가지를 따로 뗄 필요가 없어 추가 설명 편을 만들지 않는다(사용자 결정, 2026-08-27).

검색으로 들어온 독자가 앞 글 없이 읽을 수 있어야 하므로 척추는 독립으로 세운다. 편집 거리와의 관계는 표를 채운 뒤 보상으로 배치한다.

### 2.3 절 구성

1. **부분수열이란** — 지우기만 하고 순서는 지켜 남긴 것. 부분문자열과의 차이는 떨어질 수 있는가. `ACCGGT`로 `ACGT`·`CCGG`·`AT`이 되고 `GCT`·`CA`가 안 되는 이유(순서 위반). 공통 부분수열 → 최장 공통 부분수열. 도판 `subsequence.svg`.
2. **모두 세어 보면** — 부분수열은 인덱스 부분집합 하나에 대응하므로 `2^n`개다. 서로 다른 문자열로 세면 중복 때문에 더 적다(`ACCGGT`는 36개)는 조건을 붙인다. 어느 쪽으로 세도 지수라 완전탐색은 못 쓴다.
3. **부분 문제** — `L(i, j)`는 `X`의 앞 `i` 글자와 `Y`의 앞 `j` 글자, 곧 두 접두사의 LCS 길이. 답은 `L(n, m)`. 기저는 한쪽이 비면 0.
4. **마지막 두 글자가 같은가** — 짝짓기(matching)라는 말을 세운다. 공통 부분수열 하나는 순서를 지키며 같은 글자끼리 이은 짝짓기 하나에 대응한다. `정리 1`(같으면 마지막 쌍을 짝지어도 손해가 없다)과 `정리 2`(다를 때 두 갈래가 전부다)를 각각 증명으로 닫는다. 도판 `case-split.svg`.
5. **표 채우기** — 기저 두 줄, 같으면 왼쪽 위 대각선에서 하나 늘리고 다르면 위·왼쪽 중 큰 값을 가져온다. `writers`/`vintner` 표를 끝까지 채워 4와 `iter`. 도판 `table.svg`.
6. **바꾸기를 빼면 LCS가 남는다** — `정리 3`: 삽입·삭제만 허용한 편집 거리는 `n + m - 2|LCS|`다. 증명은 정렬의 열을 세는 것으로 끝난다. `writers`/`vintner`에서 `14 - 8 = 6`이고, 바꾸기를 허용하면 5다. 그 차이 1이 바꾸기 한 번이 삽입·삭제 두 번을 대신한 자리다.
7. **최단 경로를 최장 경로로 뒤집기** — 격자 항등식 `n + m - 2d`. 같은 격자에서 비용 최소화와 대각선 최대화가 같은 문제다. 대각선은 두 글자가 같은 칸에서만 놓을 수 있다는 제약이 LCS 쪽 해석을 만든다. 도판 `path-flip.svg`.
8. **코드와 비용** — C++ 의사코드. `O(nm)` 시간·공간, 길이만 필요하면 두 행으로 `O(min(n,m))`. 답 복원은 앞 글의 되짚기와 같은 원리이므로 링크로 넘긴다. `abc`/`acb`는 LCS가 `ab`와 `ac` 둘이라는 예로 "답이 여럿"도 같은 링크로 넘긴다.
9. **핵심 정리** callout → **이어지는 글**(Sequence Alignment 예고, 하이퍼링크 없이 텍스트만) → **마치며**.

절 제목에 번호를 직접 쓰지 않는다. `numbered: true`가 붙인다.

### 2.4 용어와 기호 도입 순서

- 부분수열·부분문자열: 1절. 이 글의 중심 용어이므로 가장 먼저.
- `X`, `Y`와 길이 `n`, `m`: 3절 첫 문단. 원문 표기를 그대로 쓴다.
- 접두사: 3절. 원문이 `X_i`를 부분 수열이라 부른 자리를 접두사로 바로잡아 도입한다.
- `L(i, j)`: 3절. 원문은 `LCS(i, j)`로 적었으나 본문 수식에서는 짧은 `L`을 쓰고 첫 도입 문장에서 둘이 같은 것임을 밝힌다.
- 짝짓기(matching): 4절. 공통 부분수열을 논증 가능한 대상으로 만드는 말. 앞 글의 정렬(alignment)과 어떻게 다른지는 6절에서 밝힌다.
- 정렬(alignment): 6절. 앞 글에서 세운 말을 다시 쓰되, 이 글만 읽는 독자를 위해 한 문장으로 다시 정의한다.
- 격자·경로·대각선: 7절.

## 3. 계산 예시 (검증용 원자료)

모든 값은 코드로 확인했다. LCS는 표준 점화식, 편집 거리는 단위 비용으로 계산했다.

### `ACCGGT` 의 부분수열

- 인덱스 부분집합: `2^6 = 64`개. 서로 다른 문자열: **36**개.
- `ACGT`·`CCGG`·`AT`은 부분수열, `GCT`·`CA`는 아니다(원문 판정과 일치).

### `writers` / `vintner` (원문 예시)

행이 `writers`, 열이 `vintner`인 LCS 표:

```
      -  v  i  n  t  n  e  r
   -  0  0  0  0  0  0  0  0
   w  0  0  0  0  0  0  0  0
   r  0  0  0  0  0  0  0  1
   i  0  0  1  1  1  1  1  1
   t  0  0  1  1  2  2  2  2
   e  0  0  1  1  2  2  3  3
   r  0  0  1  1  2  2  3  4
   s  0  0  1  1  2  2  3  4
```

- LCS 길이 **4**, 최장 공통 부분수열은 `iter` **하나뿐**이다(원문의 "눈으로 확인" 주장이 맞다).
- 삽입·삭제만 허용한 편집 거리 **6** `= 7 + 7 - 2 × 4`.
- 바꾸기까지 허용한 편집 거리 **5**. 차이 1이 바꾸기가 삽입·삭제 한 쌍을 대신한 자리다.

### DNA 두 서열 (원문 예시)

- `X` 23자, `Y` 37자. LCS **23**. 곧 `X`가 통째로 `Y`의 부분수열이다(탐욕 매칭으로도 확인).
- 삽입·삭제만 허용한 편집 거리 **14** `= 23 + 37 - 2 × 23 = 37 - 23`. 바꾸기까지 허용해도 14다.
- 본문에서는 표를 그리지 않고 도입의 동기로만 쓴다.

### `abc` / `acb`

- LCS 길이 2, 답이 `ab`와 `ac` **둘**이다. "답이 여럿일 수 있다"의 최소 예시.

### `acbcdb` / `cadbd`

- 원문의 정렬(Sequence Alignment) 절 예시다. 이번 범위 밖이므로 쓰지 않는다. (참고로 LCS 3, 편집 거리 4.)

## 6. 남은 불확실성 (리뷰 판정 대상)

- 4절의 '짝짓기'와 6절의 '정렬'이 독자에게 두 개의 다른 개념으로 읽힐 위험이 있다. 짝짓기는 같은 글자만 잇고 정렬은 모든 열을 적는다는 차이를 6절에서 한 문장으로 명시하되, 그것으로 충분한지는 리뷰가 판정한다.
- 7절의 격자 그림은 5절의 큰 표가 아니라 작은 격자(4×4 수준)로 그려 항등식만 보인다. 독자가 두 격자를 같은 것으로 오해하지 않도록 본문에서 예시가 바뀐다는 것을 밝히되, 그 한 문장으로 충분한지는 리뷰가 판정한다.
- 원문의 "왼쪽 표 / 오른쪽 표"는 원문 이미지 두 개를 가리키는 표현이다. 본문에서는 표 두 개를 나란히 두지 않고 같은 격자에 두 해석을 얹는 방식으로 옮긴다. 원문 구조에서 벗어나는 지점이므로 리뷰에서 원문 충실도(L6)로 판정받아야 한다.
- 브라우저 렌더는 확인할 수 없다. 도판은 값·팔레트·viewBox 범위만 검사한다.
