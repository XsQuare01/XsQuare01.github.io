# 추가 설명 — 곱셈 순서 복원 (dp-3-traceback) 설계

- 날짜: 2026-07-31
- slug: `dp-3-traceback`
- 소스: 노션 밖 확장(강의 노트에 없음). 기반은 [dp-3](/blog/dp-3)(구간 DP / 행렬 곱셈 순서).
- 형제 선례: `dp-2-traceback`(동적 계획법 ②의 선택 복원) — 구조·조판·목소리를 그대로 따른다.

## 목표와 동기

dp-3의 `m[i][j]`는 최소 *비용*만 담는다. 정답 `m[1][n]`을 알아도 **어떤 괄호 순서로 곱해야 그 비용이 나오는지**는 표에 적혀 있지 않다. 이 페이지는 채우는 동안 승리한 분할점 `k`를 함께 기록해, `(1,n)`에서 재귀로 실제 괄호화를 복원하는 방법을 다룬다. dp-3 "더 나가면"이 예고한 확장이다.

`dp-2-traceback`이 "값과 구성은 다르다 → 표를 거꾸로 읽기 → 예시 → 코드 → 동점의 미묘함"으로 갔듯, 이 페이지도 같은 골격을 쓰되 1차원 되짚기가 아니라 **분할점 기록 + 재귀 복원(이진 파스 트리)**으로 옮긴다.

## 핵심 아이디어 · 검증

- `m[i][j]`를 갱신하는 `min` 비교에서 이긴 `k`를 `split[i][j]`에 저장한다.
- 복원 재귀: `build(i,j)` = `i==j`면 `Mᵢ`, 아니면 `"(" + build(i, split[i][j]) + build(split[i][j]+1, j) + ")"`. 시작은 `build(1,n)`.
- 이 재귀 호출 구조가 곧 **이진 파스 트리**다. 내부 노드는 분할점 `k`(마지막 곱), 잎은 개별 행렬 `Mᵢ`.
- **예시 검증** `d=[3,2,4,2]`:
  - `M[1,3]=28`은 `k=1`에서 나왔으므로 `split[1][3]=1`.
  - `M[2,3]=16`은 `k=2`(유일 후보)에서 나왔으므로 `split[2][3]=2`.
  - `build(1,3)` = `"(" + build(1,1) + build(2,3) + ")"` = `"(" + "M₁" + "(M₂M₃)" + ")"` = **`(M₁(M₂M₃))`**.
  - 이 괄호화의 비용은 dp-3에서 계산한 28과 일치(오른쪽부터 묶기, 더 저렴한 쪽).

## 본문 구성 (dp-2-traceback 골격)

1. **오프닝 blockquote** — dp-3 링크. "표는 최소 비용만 담는다. 어떤 괄호 순서였는지는 어디에도 적혀 있지 않다. 강의 노트 밖 확장으로 그 구성을 복원한다."
2. **callout `이 글에서 다루는 내용`** 불릿 4~5: 값 vs 구성, 승리한 분할점 `split[i][j]` 기록, `(1,n)`에서 재귀 복원(파스 트리), `d=[3,2,4,2]`로 `(M₁(M₂M₃))` 확인, 동점·`split` 표 공간.
3. **## 값과 구성은 다르다** — `m[1][3]=28`은 "28이 최소"라는 값만 말한다. 어느 `k`가 그 최소를 냈는지(구성)는 별개 질문이고, 그 승자는 표를 채우는 `min` 비교에서 이미 결정돼 있다. 표를 지우지 않으면 그 정보는 남는다.
4. **## 분할점을 기록하기** — `m[i][j]`가 갱신될 때 그 `k`를 `split[i][j]`에 적는다. 안쪽 루프에 조건부 저장 한 줄을 더한다. (코드 조각으로 제시.)
5. **## 거꾸로 짜맞추기** — `build(i,j)` 재귀 설명: 기저 `i==j`는 잎 `Mᵢ`, 그 외에는 `split[i][j]`로 좌·우를 나눠 괄호로 감싼다. 이 재귀가 이진 파스 트리를 그린다.
6. **## 예시로 복원** — `d=[3,2,4,2]`, `split[1][3]=1`·`split[2][3]=2`로 `build(1,3)`을 단계별로 펼쳐 `(M₁(M₂M₃))`를 얻는다. → SVG.
7. **## 코드** — `split` 기록형 `matrixChain` 발췌(안쪽 루프에서 argmin `k` 저장)와 재귀 `reconstruct`(괄호 문자열 반환). C++ 의사코드.
8. **미묘한 점 `<div class="callout callout-simple">`** — ① 동점: 여러 `k`가 같은 최소를 내면 유효한 괄호화가 여럿이다. argmin에서 `<`를 쓰느냐 `≤`를 쓰느냐가 어느 갈래를 남길지 결정한다("유일한 정답"이 있어서가 아니다). ② 복원은 `split` 표(O(n²) 공간)를 요구한다 — 비용값만으로는 순서를 되짚을 수 없다. 복원된 괄호화는 잎이 `n`개, 내부 노드가 `n-1`개인 완전 이진 트리다.
9. **## 마치며** — 표는 값을 구하면서 구성 정보도 남긴다. 분할점 하나만 함께 적어 두면 비용에서 순서를 되살린다. 끝줄 `[동적 계획법 ③ →](/blog/dp-3)`.

## 코드 (C++ 의사코드)

분할점 기록(dp-3의 `matrixChain`에 한 줄 추가):

```cpp
// split[i][j]: m[i][j]의 최소를 낸 마지막 곱의 분할점 k.
vector<vector<int>> split(n + 1, vector<int>(n + 1, 0));
// ... 안쪽 k 루프에서:
long long cost = m[i][k] + m[k+1][j] + 1LL*d[i-1]*d[k]*d[j];
if (cost < m[i][j]) { m[i][j] = cost; split[i][j] = k; }
```

복원 재귀:

```cpp
// split 표를 따라 [i,j]의 괄호화를 문자열로 되짚는다.
string reconstruct(const vector<vector<int>>& split, int i, int j) {
    if (i == j) return "M" + to_string(i);            // 잎: 행렬 하나
    int k = split[i][j];                              // 이 구간의 마지막 곱
    return "(" + reconstruct(split, i, k)
               + reconstruct(split, k + 1, j) + ")";
}
// 호출: reconstruct(split, 1, n)  →  "(M1(M2M3))"
```

## dp-3 본편 링크 갱신 (이 브랜치에 포함)

dp-3의 "더 나가면" 절 마지막 문장은 현재 하드 링크 없이 프로세만 있다("그 복원 방법은 추가 설명 페이지에서 따로 다룬다"). 이 페이지가 생기면 그 문장을 하드 링크로 바꾼다:

`그 복원 방법은 [추가 설명 — 어떤 순서로 곱했는지 되짚기](/blog/dp-3-traceback)에서 따로 다룬다.`

## 범위 밖

- Hu–Shing `O(n log n)` 등 최적 괄호화의 빠른 알고리즘은 다루지 않는다.
