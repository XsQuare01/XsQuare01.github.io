# 도판 팔레트 — 도식의 색에 역할 이름을 붙인다 (설계)

- 날짜: 2026-08-21
- 상태: 승인됨 (사용자 확인, 시안 검토 후)
- 이슈: [#237](https://github.com/XsQuare01/XsQuare01.github.io/issues/237)
- 브랜치: `feat/diagram-palette`
- 시안: `Docs/diagram-palette-mockup.html` (사용자 검토 완료)

## 목표

도식 181개가 쓰는 116색에 역할 이름을 붙여 18색으로 줄인다. 앞으로 그리는 도식이 그 18색만 쓰게 하고, 인라인되는 단계 도식은 CSS 토큰으로 색을 받게 한다. 기존 도식의 색은 옮기지 않는다.

## 이슈의 전제 하나를 정정한다

#237은 「도판이 밝은 종이 위에 있어야 하는가」를 선행 결정으로 세웠다. 코드를 확인하니 그 질문이 성립하지 않는다.

**이 사이트에는 다크 모드가 없다.** `prefers-color-scheme`도 `data-theme`도 없고 토큰이 한 벌뿐이다. 어두운 판은 테마가 아니라 **의도된 모티프**다. `.prose pre`와 `.astro-code`가 도판과 같은 `--term-bg`/`--term-fg`를 쓰고, 셋 다 #41 「터미널 크롬 + 논문 본문」에서 왔다. 도식은 코드블록과 같은 표면에 앉아 있다. 밝은 판으로 옮기면 그 짝이 깨진다.

그래서 팔레트는 어두운 판 위에서 정한다. 사이트의 다크 모드 팔레트(`DESIGN_DIRECTION.md` §5의 미결 항목)와는 다른 것이다.

## 지배 원칙

`DESIGN_DIRECTION.md`는 도식을 한 번도 언급하지 않는다. 「강조색은 잉크블루 단 하나, 색을 늘리면 블로그 템플릿으로 추락한다」는 규율은 크롬과 산문을 겨냥한 것이고, 걷어낼 목록의 「오렌지 `#f97316` 및 파생 전부」는 도판까지 오지 않았다(도식 61개가 아직 쓴다).

이 팔레트는 새 규칙이 아니라 **그 문서의 빠진 절**이다. 원칙은 이렇게 둔다.

**크롬에서 색은 장식이라 하나면 되지만, 도판 안에서 색은 데이터다.** 채택·거부·현재를 괘선이나 번호로 대신할 수 없다. 대신 대가를 치른다 — 역할 이름이 없는 색은 쓰지 않고, 계열을 다섯에서 멈춘다. 여섯 번째 뜻이 필요하면 색이 아니라 모양·굵기·점선으로 가른다.

계열마다 `선·글자` / `옅은 짝` / `채운 영역` 셋을 넘지 않는다. 채움은 대비 1.4~2.0:1이므로 **글자를 얹지 않고** 영역 표시로만 쓴다.

보라는 **초록·파랑·빨강으로 가를 수 없을 때만** 꺼낸다. 집합 구분, 두 번째 자료구조, 보류 상태가 그 경우다.

## 팔레트가 사는 곳

값이 두 곳에 있어야 한다.

- **`src/styles/global.css`** — `--dg-*` 18개. 인라인된 단계 도식에 실제로 색을 주는 쪽이다.
- **`docs/design/DIAGRAM_PALETTE.md`** — 역할·값·쓰임·대비 표와 저작 규칙. `<img>`로 들어가는 도식에는 CSS가 닿지 않으므로, 그릴 때 붙여 쓸 hex가 문서에 있어야 한다.
- **`docs/design/DESIGN_DIRECTION.md`** — 포인터 한 줄. 그 문서의 「다크 모드 팔레트 미확정」과 **다른 것**임을 명시한다.

같은 값이 두 곳에 있으면 어긋난다. 그래서 검사가 둘을 대조한다(아래).

배경은 값을 베끼지 않고 `--dg-bg: var(--term-bg)`로 정의한다. 판과 도식의 검정이 **구조적으로** 어긋날 수 없게 하는 것이 목적이다.

## 적용 — SVG 파일을 바꾸지 않는다

class를 붙이는 방법은 기각했다. 도식 하나에 class 60개를 다는 일이고, 속성과 class가 서로 다른 색을 가리키게 될 여지가 생긴다. 대신 **속성값 선택자**를 쓴다.

```css
.svg-steps svg [fill="#4ade80"]   { fill: var(--dg-green); }
.svg-steps svg [stroke="#4ade80"] { stroke: var(--dg-green); }
```

CSS가 프레젠테이션 속성을 이기므로, 인라인되면 토큰이 적용되고 `<img>`로 물러나면 속성값이 그대로 남는다. **SVG 파일은 한 글자도 바뀌지 않는다.** hex가 181개 파일에서 전부 소문자이므로(확인함) 선택자가 확실히 맞는다.

오늘은 토큰 값이 속성값과 같아 시각적으로 no-op이다. 값이 달라지는 날 인라인 도식이 따라온다. 그것이 이 층의 전부이며, 그 이상은 지금 필요 없다.

규칙은 `.svg-steps svg` 안으로 한정한다. 본문의 다른 요소가 같은 hex를 속성으로 쓰더라도 영향받지 않게 하기 위해서다.

## 강제

`test/palette.test.mjs`에 넣는다. 검사 넷이다.

1. `global.css`의 `:root`가 `--dg-*` 18개를 정의하고, 이름과 값이 문서 표와 같다. `--dg-bg`는 별칭(`var(--term-bg)`)이므로 `--term-bg`의 값을 따라가 비교한다.
2. 문서 표의 값이 CSS와 한 글자도 다르지 않다(레거시 표의 값은 팔레트에 없어야 한다).
3. `*-steps.svg`의 모든 색이 팔레트 안에 있고 소문자다. **기존 180개는 검사하지 않는다** — 레거시를 허용 목록에 넣으면 검사가 스스로를 무력화한다.
4. 팔레트의 18색마다 `[fill=…]`과 `[stroke=…]` 규칙이 **둘 다** 있다. 채움색에 stroke 규칙은 쓸 자리가 없지만 예외를 두지 않는다 — 예외를 허용하면 검사가 「어느 값에 어느 규칙이 필요한가」라는 목록을 따로 알아야 하고, 그 목록이 다음 드리프트의 자리가 된다.

그리고 `.github/workflows/review-gate.yml`에 `npm run test:js`를 더한다. **지금 CI는 JS 테스트를 하나도 돌리지 않는다** — #236에서 만든 16개도 강제되지 않는 상태다. 이 결정이 검사의 거처를 정하는 일이므로 함께 고친다.

## 배경 정합

`--term-bg`를 `#15171c` → `#0f1117`로 바꾼다. 한 줄이다.

도식 181개는 손대지 않는다. 그 안의 색(면 `#1e293b`, 선 `#334155` 등)이 모두 `#0f1117` 위에서 골라진 것이므로, 배경을 밝히면 181개의 내부 대비가 조금씩 흔들린다. 반대 방향이 옳다.

영향받는 곳은 셋뿐이다 — `.prose pre`, `.astro-code`, `.post-figure`. `--term-fg` 기준 대비는 11.3:1 → 11.8:1로 오른다. 도판 테두리 `#23262e`는 1.19:1 → 1.25:1로 조금 또렷해진다.

## 발행된 그림이 바뀌는 곳

`public/images/convex-hull-2/scan-steps.svg` 하나다. 단계 도식은 검사 3의 대상이므로 팔레트를 지켜야 한다. 레거시 세 색을 대체값으로 바꾼다.

- 초록 `#34d399` → `#4ade80` — 12곳(fill 5, stroke 7). 초록이 살짝 밝아진다(9.8:1 → 10.8:1).
- 빨강 `#ef4444` → `#f87171` — 5곳(전부 stroke, pop 표시의 ✕와 거부된 경로). 빨강이 살짝 옅어진다(5.0:1 → 6.8:1).
- 회색 상자 `#1f2937` → `#1e293b` — 1곳.

시안 §06에서 초록과 회색 상자의 전후를 확인했다. **빨강은 시안에 없었다** — 자체 검토에서 찾았고, 같은 계열 안의 한 단계 차이이므로 팔레트 결정을 다시 묻지 않는다. 다만 구현 후 브라우저 확인 항목에 넣는다.
