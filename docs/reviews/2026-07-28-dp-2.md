### 🟡 [L7] 입력 범위와 기저 조건이 닫히지 않는다

- severity: 🟡
- source: L
- rule_id: L7
- location: src/content/posts/dp-2.md:27,91-97,109-118
- quote: "하루뿐이면 그날을 고르는 것 말고 다른 도리가 없으니 $S(1)=a_1$이다."
- message: 일급이 음수가 될 수 있는지, 일을 하루도 고르지 않아도 되는지, `n=0`이 입력될 수 있는지 밝히지 않았다. 현재 문제 정의는 빈 선택을 금지하지 않으므로 음수 일급 하나에서는 최댓값이 0일 수 있지만 본문은 $S(1)=a_1$로 둔다. 코드도 `n=0`이면 `r[1]`과 `a[1]`에 접근한다. 또한 91행은 $n=1,2$를 따로 정한다고 설명하지만 실제로 제시한 기저는 $S(0),S(1)$이며 점화식은 $n=2$부터 적용한다. 양수 예제의 최적값 15, 포함·제외의 MECE 분할, 교환 논증과 상계·하계 증명, 점화식, 2행 표 값, $O(n)$ 시간과 $O(n)$ 공간 계산은 독립 검산에서 맞았다.
- recommendation: 입력 계약을 `n>=1`, `a_i>=0`처럼 명시해 현재 기저와 코드를 정당화하거나, 빈 선택과 `n=0`을 허용한다면 $S(1)=\max(0,a_1)$과 `n==0` 처리를 넣는 방향을 권고한다. 기저 설명은 $S(0),S(1)$을 두고 $n>=2$에서 점화식을 적용한다고 바로잡는다.
- gate_effect: warn

### 🟡 [L2] 2행 상태가 필요한 이유가 잘못 연결된다

- severity: 🟡
- source: L
- rule_id: L2
- location: src/content/posts/dp-2.md:103-105,128-150
- quote: "$S(i)$ 하나만 저장하면 $i-2$ 시점 값이 이미 지워진 뒤라 참조할 수 없어, 매 순간 \"$i$번째 날에 일하지 않았을 때\"와 \"일했을 때\"의 최선을 나란히 들고 간다."
- message: 문제 정의, 포함·제외 분기, 점화식, 증명, 구현, 예제, 확장, 결론의 큰 흐름과 선행 글 연결은 자연스럽고 결론도 다음 편 예고로 닫힌다. 그러나 이 문장은 1차원 DP 배열과 한 개의 굴림 변수를 같은 뜻으로 섞고, 2행 상태가 점화식 계산에 필수인 것처럼 설명한다. $S(0..n)$ 배열을 저장하면 $S(i-2)$는 지워지지 않으며, 뒤에서 밝히듯 변수 두 개만으로도 계산할 수 있다. 승인된 설계에서 2행 표는 노션 코드의 포함·제외 상태를 설명하려는 선택이므로 필요성보다 교육적 대응 관계를 앞세워야 한다.
- recommendation: 2행 상태를 택한 이유를 "포함·제외 사례를 코드에 그대로 드러내기 위해서"라고 설명하고, 1차원 $S$ 배열이나 직전 두 값으로도 같은 점화식을 계산할 수 있다는 사실을 이 대목에서 구분한다.
- gate_effect: warn

### 🟢 [L3] 표와 최댓값 용어가 일부 섞인다

- severity: 🟢
- source: L
- rule_id: L3
- location: src/content/posts/dp-2.md:16-19,39,103-140
- quote: "포함·제외 사례 분석: 두 선택지를 나눠 각각의 최적값을 비교한다" / "상향식 2행 테이블"
- message: 포함·제외, 최적해, 점화식, 선택한 날짜의 뜻과 기호 $S$, $a_i$, `r[i][0/1]`은 대체로 일관된다. 다만 수치 목적값은 본문 대부분에서 "최댓값"인데 목차에서만 "최적값"이라 하고, 같은 자료 구조를 "테이블"과 "표"로 번갈아 부른다. 의미 오류는 아니지만 핵심 용어를 처음 배우는 독자에게 서로 다른 개념처럼 보일 수 있다.
- recommendation: 수치에는 "최댓값", 해의 구성에는 "최적해"를 쓰고, 2행 자료 구조는 "표" 또는 "테이블" 하나로 통일한다.
- gate_effect: info

### 🟡 [L7] O(1) 공간이면 복원을 포기해야 한다는 표현이 절대적이다

- severity: 🟡
- source: L
- rule_id: L7
- location: src/content/posts/dp-2.md:148-150
- quote: "표를 지우고 변수로 줄이는 순간 이 복원은 포기해야 한다."
- message: 직전 두 값만 굴리면 최적값 계산의 추가 공간이 $O(1)$이라는 주장은 맞고, 표를 보존하면 마지막 상태에서 이전 상태를 따라가며 선택일을 복원할 수 있다. 그러나 값만 한 번 계산하는 현재 방식에서 즉시 되짚을 수 없다는 뜻과, 어떤 방식으로도 복원할 수 없다는 뜻은 다르다. 재계산으로 시간을 더 쓰거나 별도 결정 정보를 저장하는 시간·공간 절충이 가능하므로 현재 문장은 비용 모형을 생략한 과한 단정이다.
- recommendation: "현재의 한 번 순회와 $O(n)$ 시간까지 유지하면서 직접 되짚으려면 이전 상태나 선택 정보를 보존해야 한다"처럼 조건을 붙이고, $O(1)$ 공간 버전은 값만 구하는 구현임을 명시한다.
- gate_effect: warn

- message: 검토 완료, 이슈 없음. 이 실행 환경에는 `notion-search`나 `notion-fetch`가 없어 실제 노션 페이지의 본문, 이미지, 제목, 인용을 가져오지 못했다. 따라서 현재 포스트가 노션 원문을 빠짐없이 보존했는지, 원문에 없는 내용을 자의로 보탰는지는 판정할 수 없다. 별도 승인된 설계 명세는 문제 정의, $2^n$ 완전탐색, 포함 A·제외 B, 최적 부분구조 증명, 2행 코드, `[3,5,6,10]` 표, 복원과 $O(1)$ 확장의 출처 구분이 현재 글의 구조와 일치함을 확인해 주지만 원문 충실성의 증거로 대신 쓰지 않았다.
- recommendation: Notion 도구를 사용할 수 있는 환경에서 명세에 적힌 실제 페이지를 검색·가져온 기록과 함께 대조하고, 특히 복원한 예시 숫자와 노션 밖 확장 표시를 재확인한다.
- gate_effect: info
